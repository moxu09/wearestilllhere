# 秋奈 ATM／超商代碼查單補漏

2026-10-26：付款通知仍為主要入帳來源，另加主動查單補漏；不保證銀行／超商尚未回報的付款可提前確認。

- 先安裝 `supabase/migrations/20261026000000_qiunai_ecpay_inquiry.sql`，僅 service_role 可讀節流紀錄及執行函式。
- 網站 `/api/payments/ecpay/service/inquiry` 僅接受機器人 HMAC 簽章及五分鐘內時間戳。人工按鈕須同時匹配秋奈店別、付款本人與原頻道。
- 小奈每 30 秒最多選一筆近七天、建單至少一分鐘、已取號的 ATM／CVS 待付款單；依上次查詢時間輪替。
- 單筆自動查詢冷卻五分鐘，人工查詢冷卻至少一分鐘；共用資料庫租約及商戶查詢間隔六秒。403 時持久化停止此查單功能 30 分鐘。既有管理頁的秋奈 ATM／CVS 查單也走同一限制。
- 查詢回應必須通過綠界檢查碼、商戶、訂單、原綠界交易序號、付款方式與金額核對。尚未付款、查詢失敗及模擬付款均不得入帳。
- 已有同額管理員發錢／人工購幣紀錄，或原訂單已付款、取消、缺失時，停在人工覆核；不可自行猜測補款關聯。已明確關聯且完成的防重複入帳紀錄可正常通過。
- 確認付款時，同一資料庫交易寫入實際付款時間；保留原取號資料，並交由現有入帳租約及金融操作唯一鍵處理後續，重複查詢不再發幣。
- 新發出的 ATM／CVS 繳費訊息附「我已付款，重新查詢」按鈕。顯示付款已確認與後續入帳完成為不同狀態。
- 回呼解析相容等值數字／字串狀態，但仍核對內外商戶、AES 解密、非模擬付款與原交易；分類錯誤日誌不記錄通知內容、金鑰或付款帳號。歷史錯誤未保存原始通知，不能僅依通用錯誤訊息判定確切原因。

隔離資料庫驗證：`MEMBERSHIP_PGLITE_MODULE=/path/to/@electric-sql/pglite node scripts/testEcpayInquiryDatabase.js`（腳本在秋奈機器人倉庫）。
網站：`node --test tests/*.test.mjs`、帶正式建置環境的 `npm run build`。正式驗證只查現有付款，不建立或模擬真實收款。
